# 从产品/机会选择客户与渠道路径

## 输入边界

- 用户的产品/服务、可供数量、差异化依据、目标市场与语言、交付能力和可用获客预算。
- 区分使用者、购买决策者、付款方与渠道中间人。不要因为同一个词出现在公司简介中就认定为买家。
- 已有客户/渠道材料、用户明确允许的联系范围，以及本次交付是路径比较还是具体客户开发。后者可按需组合 customer-development 的方法，而非强制进入下一阶段。

## 客户与渠道证据

- 公司业务页面、品类目录、门店/进口业务说明支持“候选角色/品类相关”，不证明当前采购需求。
- 用户的真实订单/询盘/访谈材料支持其覆盖的特定客户与时间范围；陈述未核实时保留 `user_statement`。
- 搜索、社媒与平台曝光保留 `community_signal` 或明确的页面观察范围；从曝光推导成交潜力时只能标 `inference`。
- 联系入口只使用用户材料或公开业务渠道中实际出现的地址/表单，记录 URL/文件定位与最近核对时间；职位和邮箱不得按命名规则猜测。
- 关键主张保留真实 Evidence/source receipt（有则填写）与原文位置；一个公司页面能支持多个字段，但不能冒充多个独立来源。

## 比较方法

- 每条路径写清到达用户的方式、谁决策、如何交付、谁承担退货/服务、可能的收入与成本结构。
- 只比较具备来源和同一期间/币种/分母的经济性。CAC、转化、毛利或渠道费缺失时列为待测，不填行业“常见值”。
- 优先验证能改变路径排序的假设，例如渠道是否覆盖目标客群、能否满足最小订单和服务要求；不要把渠道数量当作有效触达量。
- 成功条件必须针对可观察的购买信号；曝光、打开和点赞与明确回复、合格询盘、订单分列。

## 输出与授权

按需使用 [客户与渠道路径](../templates/channel-path.md)，保留候选、依据、实验和停止条件。只交付草稿或建议；未经对应授权不联系候选、批量采集个人信息、注册渠道或发布店铺内容。
