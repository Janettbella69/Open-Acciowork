# 工作区检查点与恢复

在保存的项目中打开 **Workspace recovery / 工作区恢复**，选择运行开始前的恢复点，
查看全部新增、替换、移除的文件和目录，再勾选确认并恢复。恢复前的当前工作区会另存
为一个恢复点；返回列表后可用同一流程恢复该副本。超过 100 项的变更分页展示，总数
与移除文件数始终保留。网络响应不确定时可查询结果或重试同一次恢复。

这项能力恢复项目 `workspace/` 内的文件，不撤销证据、决策、商业操作、审批或对话。
历史产物仍可下载，恢复出的文件登记为新的人类版本，关联已有同内容来源。
恢复不会运行模型、回放 Bash、调用商业 Connector 或自动续接原会话。

## 为什么需要宿主检查点

Claude Agent SDK 原生检查点继续启用。[官方文件检查点文档](https://code.claude.com/docs/en/agent-sdk/file-checkpointing)
说明其覆盖原生文件编辑工具，但不跟踪 Bash 修改。应用在每个新 Run 真正进入 SDK
之前保存完整的可支持工作区文件树，因此也能恢复 Bash 改写或删除的文件。

同一项目的运行通过跨进程租约排队，其他项目可继续执行。租约覆盖初始检查点、SDK
执行和终态清理；取消快照线程必须等其释放文件描述符，不能提前让下一位写入者进入。
取消排队任务、修复孤儿运行的产物扫描也检查租约，防止把另一 Run 正在写的文件认作
自己的产物。人工恢复还要求项目没有非终态运行或仍在清理的执行者。

运行起点绑定 `project_id/run_id/trace_id`，同一 Run 的审批恢复复用原起点。
已有 `started_at`、但没有检查点的旧 Run 不会补造“原始状态”。另行创建的重试 Run
拥有自己的起点。检查点失败时 Run 失败并保存原因，SDK 不会带着一个不完整快照启动。

## 存储与中断协议

工作区检查点放在项目的 `workspace-checkpoints/`。文件内容复用不可变的
`artifact-versions/{sha256}`，清单包含路径、大小、哈希、所有者权限位和空目录。
目录、文件与整个清单均验证；软链接、硬链接、FIFO 等特殊条目不进入快照，也不会被
静默跳过。读取与复制受大小、数量、路径深度和清单上限约束。

恢复按以下顺序执行：

1. 在当前项目权限、审阅者和会话范围内生成预览，绑定当前树与目标树的指纹，有效期
   10 分钟。执行前再次确认权限、空闲状态、指纹与容量；旧预览不会覆盖新工作。
2. 保存当前树的安全检查点，把目标文件复制到本次审阅专属的 staging 目录并校验。
3. 将完整授权意图写入 `pending-workspace-restore.json`，fsync 后通过原子且禁止覆盖
   目标的 rename，把当前工作区移到 `workspace-retained-{restore_id}`，再发布 staging。
4. 校验目录身份和内容，登记新产物版本，持久化 `applied`，最后清除待恢复意图。

重启后，在下一次工作区访问、新 Run 创建或恢复操作时核对授权意图，继续完成已经
批准的目录切换。缺失工作区不会先被 mkdir 成空目录；出现未知替代目录时停止并保留
所有副本。授权落盘前遗留的 staging 只在其匹配未执行审阅时清理；重试复用同一个安全
检查点。`applied` 已持久化后，即使用户又修改了文件，清理残留意图也不会重复替换文件。

应用冷备份验证检查点清单、内容与已执行恢复的关联，恢复后的检查点仍可再用。
待执行目录切换绑定原宿主 inode，不能在冷备份的新目录上重放；冷备份遇到待恢复意图
或 staging 会拒绝。应先在原宿主核对完成，再停机备份。这里的哈希是完整性检查，
并非对能够同时改写宿主账本与文件的操作者提供签名认证。

## HTTP 合同

全部路径以 `/api/projects/{project_id}/workspace` 为前缀：

| 方法 / 路径 | 输入与结果 |
|---|---|
| `GET /checkpoints` | 检查点摘要，按时间倒序；无需读取全部文件内容 |
| `POST /restores` | `{"checkpoint_id":"…"}`，生成变更预览，不替换文件 |
| `GET /restores/{restore_id}` | 查询已保存结果，必要时完成已批准的中断恢复 |
| `POST /restores/{restore_id}/apply` | `{"confirm_file_changes":true}`，执行或返回同次恢复的已执行结果 |

读取要求 `PROJECT_READ`；预览、执行要求 `PROJECT_WRITE`。应用在 I/O 后复验权限，
替换前再次复验。执行只接受原审阅者及原会话；拒绝未确认、过期、跨项目、撤销权限
或过时预览。成功响应 `Cache-Control: no-store`，不输出会话标识或目录 inode。
输入请求最大 1 KiB。该接口没有对应的 Agent MCP 工具。

## 当前验证与容量边界

- 每个文件最多 250,000,000 字节；单树 10,000 个文件、20,000 个条目、
  2,000,000,000 字节；清单最多 16 MiB。内容历史与产物共享 10,000 个 blob / 2 GB 配额。
- 每项目最多 500 个检查点、1,000 次审阅；保留目录副本合计最多 2 GB。达到上限会
  明确失败，不截断文件或自动删除历史；历史保留策略和管理入口尚需交付。
- 保留文件字节、目录结构和所有者权限位；不承诺 ACL、扩展属性、创建时间、group/world
  权限或链接语义。原工作区目录本身仍保留在恢复副本中。磁盘剩余空间不足会拒绝或保留
  可核对的中间状态，不声称已成功恢复。
- 本地回归使用真实 `/bin/sh` 文件修改、真实 spawn 进程退出、两个 RunManager 争用、
  撤销权限、过时预览、损坏副本、目录替换、取消快照线程、文本编辑中断和冷备往返。
  模型 runtime 为离线替身；不代表真实 SDK 故障注入、Linux 实机、网络文件系统或生产灾备认证。
- 所有应用 worker 必须升级后再启动；旧 worker 和外部编辑器不遵守新的运行租约。
  不支持把共享宿主文件系统当作多租户安全隔离。任意外部写入、磁盘故障和大容量性能
  仍需独立验收；不会把已发现的不一致状态强行覆盖成成功。
- 当前 Browser 发现列表为空。前端有交互测试、类型检查和构建验证，尚无本轮目视验收。
