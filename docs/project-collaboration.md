# 共享项目、成员与评论

PRD §3.7 P2 团队协作和 FR-22 的本批交付范围是：现有单部署租户中的项目成员管理
界面，以及可持久化、回复、关联对象、编辑、移除和解决的项目讨论。项目模板、
组织私有 Skill 仓库、生产身份网关和租户物理隔离仍由交付清单单独跟踪。

## 身份与成员

项目访问继续由可信网关 HMAC principal 和服务器 `ProjectAccessStore` 的成员关系
共同决定。租户必须匹配，签名角色必须等于当前项目角色；客户端表单里的账号 ID
只表示被授权对象，不能指定当前操作者。所有者不可被移除或改角色，只有所有者
能授予管理员角色，管理员可管理其他非所有者账号。

工作区“团队与评论”展示当前账号和能力；“项目成员”仅对所有者和管理员可见。
填写组织账号 ID、选择角色后，先核对具体账号/变更，再确认保存。该操作不创建
组织账号或发送邀请消息。成员以获配角色登录后，通过原有项目列表访问共享项目。

`GET /api/projects/{project_id}/collaboration` 返回当前 `actor_id`、`role`、
`identity_mode`、`can_comment`、`can_manage_members` 和 `grantable_roles`；不返回
签名凭据或会话 ID。现有 `/access` 的 POST 新增可选 `expected_revision`，DELETE
新增同名查询参数。UI 每次提交都携带已核对的 revision；服务器在跨进程成员锁内
比较并修改，冲突返回409。旧 API 调用方可以暂不传此字段，兼容已有管理脚本。

本地模式只允许本机操作者给本地项目评论，不模拟多人登录。已有本地项目不会在
切换身份部署后自动变成团队项目。此版本继续声明 `multi_tenant=false`。

## 讨论合同

| API（共同前缀 `/api/projects/{project_id}`） | 行为 |
|---|---|
| `GET /comments?before=&limit=` | 根讨论按创建序号倒序分页，默认20、最多50；返回回复数 |
| `POST /comments` | 新建根讨论，或通过 `parent_id` 回复；文本最多4000字符 |
| `GET /comments/{id}/thread?after=&limit=` | 根讨论和按创建序号正序的回复，默认50、最多100 |
| `PATCH /comments/{id}` | `edit`、`remove`、`resolve`、`reopen`；必须携带 `expected_revision` |
| `GET /comments/{id}/history` | 作者或项目管理员查看原文及逐次修改历史 |

根评论的 `anchor.kind` 可为 project、run、message、evidence、decision、artifact。
关联对象必须由服务器在同一项目解析。消息限定为保存的主 Agent 可见完整文本事件，
绑定原 Run/trace；不接受子代理消息、工具输出或其他项目的 Run。文件保留原版本
编号和校验和，界面下载的是被讨论的准确版本。标签和正文经过现有脱敏处理。
回复只能挂在根讨论下，继承其关联对象，不接受另一个目标或多层嵌套。

所有者、管理员、成员和审阅者可以评论；查看者只读。只有作者可以改写自己的
正文；作者和管理员可移除评论、解决/重开根讨论。移除是正文 tombstone，原文仍
保留在仅作者/管理员可读的历史中。解决不会禁止继续回复。讨论不自动修改证据、
决策或商业审批，也不会作为可信事实注入主 Agent。

每次新建或修改都要求16–100字符的 `request_id`（字母、数字、下划线、连字符）。
新建 ID 由项目/当前操作者/request_id 的摘要确定；同一请求同一内容重试返回已保存
对象，不重复新增。修改同样保存请求身份与指纹，先识别重试，再比较 revision；同一
请求 ID 被换内容时返回409。操作者身份来自服务器；评论记录和返回视图不保存
当前身份的认证密钥、签名或会话 ID。

## 持久化与故障边界

评论保存在 `data/collaboration/comments/{project_id}.json`，位于 Agent 工作区外。
单项目最多5000条评论（含回复），每条最多100个历史版本，整个存储最多16MiB。
读取和写入按实际序列化字节执行同一上限；请求体最多32KiB。历史验证连续序号、
创建身份、回复归属、时间顺序和合法状态转移；损坏、符号链接和非普通文件不能
被当作空历史继续写入。

项目评论锁和成员锁均覆盖跨进程操作，提交前后复验身份；撤销成员不能穿插到已经
取得成员租约的评论提交中。保存使用唯一0600临时文件、fsync 和原子替换。实际进程
在保存后退出的重试测试证明不会新增重复评论。冷备份会验证评论身份和历史结构，
并保留正文、回复、移除状态和历史；恢复到新数据目录后可继续读取。

成员、能力和评论接口的成功及错误响应均标记 `Cache-Control: no-store`。
界面打开后每15秒刷新，并在回到窗口时复查；同一视图的请求串行。切换项目、
关闭面板或失去访问权限会取消请求和移除私有内容。较早发出的能力响应不能在
权限已撤销后重新显示项目；已保存的新评论版本也不会被迟到的旧读取覆盖。
编辑冲突保留草稿，用户核对最新文本后才能明确选择应用到新版本。
