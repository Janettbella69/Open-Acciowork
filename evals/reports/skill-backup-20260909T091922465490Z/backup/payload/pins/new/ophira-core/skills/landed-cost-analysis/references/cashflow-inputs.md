# 可复算输入与证据

工具计算不验证供应商、回款信用、税率、汇率或资金可获得性。将事实来源和计算结果分开：

- 报价、付款条款：保留原件/报价时间、币种、数量、含税/不含税口径、订金与尾款条件。
  优先经同 Run 的真实 Read、Connector 或来源收据定位。引用文件名本身不等于确认了条款。
- 物流、平台费用和退款：注明费用承担方、计费单位、结算日期及估算依据。没有账单或明确
  用户假设时列为缺失项；不得默认为免费，也不得仅靠行业常见比例补成事实。
- 关税/税款：费率或适用性需可追溯的当前依据；无法确定的事项交给 logistics-customs 或
  compliance-claims 视角核实。此文件不提供通用税率或法律结论。
- 客户回款：区分签约应收、已结算现金和情景假设。订单利润、开票日与实际到账日不是同一
  现金流输入；计划可以比较假设，但不能承诺如期到账。
- 汇率：工具只收一种用户声明的币种。换算必须另行列明汇率来源/日期和计算；未知汇率
  不得由模型补出。三字母币种标签只说明单位，工具不会验证其为有效货币。

`cashflow_peak` 输入包含 `currency`、`start_date`、`end_date`、`opening_cash`、
`minimum_reserve` 与 `movements`。每条 movement 使用唯一 `id`、现金结算 `date`、
`direction`（inflow/outflow）、正 `amount`、`activity`（operating/investing/financing），
可选 `description` 和 `source_ref`。自由文本引用只是调用者标签，不是已核验 Evidence。
日期采用 YYYY-MM-DD，金额至多四位小数；不将分币单位和整币单位混用。

整理计划时避免重复：采购总价与订金/尾款二者只选一套，不同时计入；贷款到账和还本分别
列收付，利息另列；内部账户转移在同一现金范围内不构成新增收入；最低保留现金不列支出。
若首日期初现金已低于保留额，应保留期初缺口，不因当日稍后预计回款而隐藏。

在基准、乐观、悲观情景之间只改声明过的输入。每个情景分别调用计算工具，保存其完整
输入与 `input_sha256`；不要只写一个缺乏输入的资金缺口结论。情景差异是推算，不是事实。

解释结果时核对 `reconciliation_difference` 为零，说明未输入的项目不在计算中。
`funding_for_opening_and_daily_closes` 和 `funding_if_outflows_settle_first` 是在所给
计划下满足阈值的额外资金量；工具不执行注资，也不推荐贷款产品。
