# 项目与会话删除：实施合同

**状态：仍在实现，尚无用户删除 API 或确认界面。** 当前交付的是底层删除事务、
应用访问互斥及中断恢复，不能据此把 PRD §3.9 的项目/会话删除标为完成。
所有本批删除验证仅使用测试临时目录，没有操作真实用户项目。

## 已实现的事务边界

`erasure_files.py` 接收由主机业务服务构造的精确计划：待删除文件、待移除空目录、
共享文件中需要保留的字节，以及由调用方验证的最小范围/身份信息。它没有 HTTP、
CLI 或 Agent 工具入口；**不能把未经范围校验的用户文件列表直接交给它**。

1. 调用方授权、源文件长度/哈希、目录完整性和保留字节先核验，再次复验后提交。
   计划限制源内容合计 2 GiB、单文件 250 MB、20,000 文件及20,000目录、32层路径；
   单份保留内容16 MiB、合计64 MiB，整个事务记录最多16 MiB。
2. `.data-erasure/pending/` 的原子发布是不可逆提交点。提交前源数据不变；提交后
   中断需要继续清理，不能把已删除内容恢复回来。暂存区只存保留字节和清单，
   不备份将要删除的正文。
3. 删除文件和原子替换共享记录均校验原值。重启可识别已经完成的步骤，剩余替换
   使用已提交的保留字节；部分临时替换可恢复。目录只在为空时移除，额外文件、
   损坏记录、变更源字节或不安全路径使清理失败，不扩大删除范围。
4. 完成时持久写入不含文件正文/路径清单的凭证，再把完整 pending 目录原子改名后
   清理。提交前留下的 staging 和完成后的清理残留可由 `recover()` 清除；损坏的
   pending 不被当作成功。失败后的普通数据访问保持关闭，直到恢复完成。

所有目标路径使用目录描述符，不跟随符号链接，拒绝硬链接、特殊文件、越界路径、
大小写/Unicode别名以及文件/目录冲突。事务不能删除自身清单或互斥锁。保留内容
不能同时位于计划移除的目录中。凭证保留最小范围由未来业务服务的专用模型约束；
当前通用文件层不推断项目所有权，也不宣称有完整业务删除策略。

后续确认处理器须在当前授权和有界请求解析完成后，明确交还请求的共享租约，
再在独占事务内复验范围与授权。不能在仍持有共享租约时尝试升级，也不能为了
删除入口而整体绕开请求来源检查和鉴权。当前没有这种入口或租约交接实现。

## 与应用运行的互斥

已有冷备份租约继续负责整个应用与停机维护的互斥。新增
`.data-operation.lock` 负责应用内操作与删除事务的互斥，二者目的不同：

- API 请求在身份 nonce 写入之前取得共享租约，持有到完整 ASGI 响应/流结束。
  维护冲突返回409、`no-store`、`Retry-After`，保留配置的跨域响应策略。
- 独立 Run、定时扫描、前瞻意图、渠道投递和 Web Push 持有各自的租约；请求取消
  后仍工作的上传/编辑/导出等线程也自行持有租约，不依赖请求协程存活。
- 店铺浏览器宿主从构造到退出都参与租约，避免关闭 API 后浏览器仍写登录目录。
- 新进程在创建业务存储前恢复已提交的删除；另一个活进程仍持有独占租约时，
  不争抢其事务。冷备份及恢复验收拒绝未完成的删除记录，不复制或认可半完成状态。

这是一台主机、一个数据目录内的协作锁协议。当前删除独占整个部署的数据操作，
长时 Run、下载流或打开的店铺浏览器会阻止其取得锁；不强行终止它们。旧版本进程、
绕过应用直接改文件的工具、跨主机/不支持 flock 的存储、同 OS 权限攻击者不在
本批保证范围内。上线实际删除前须升级所有写入进程，不能混用不识别此锁的旧版本。

## 接下来必须完成的业务范围

| 数据 | 删除整个项目 | 删除单个会话（暂定保留已保存成果） |
|---|---|---|
| 项目工作区、版本、检查点 | 清理整个项目所属数据 | 保留项目成果；删除的会话不可再恢复 |
| Run、事件、摘要、原生SDK会话 | 清理项目全部会话 | 按会话/续接关系清理，保留内容为空的来源凭证 |
| 项目记忆、共享记忆与Agent日记 | 删除所属记忆及可明确追溯的派生上下文 | 清理该会话的可恢复上下文，保留其他会话/项目 |
| 计划、意图、权限、通知、投递、经验、店铺登录态 | 停用/清理关联记录，避免重建项目或再次外发 | 核对会话引用，不能重放已发生的副作用 |
| 讨论、模板、Skill候选、业务来源凭证 | 清理所属内容并处理引用 | 保留独立保存成果，处理已删除Run引用 |
| 其他项目独立副本、已发布共享Skill、全局凭据、旧备份、外部服务 | 必须在确认范围中单列 | 必须在确认范围中单列 |

以上是剩余实施清单，不是已完成声明。还需实现专用范围模型、授权预览/确认、
版本绑定、持久删除标记与禁止重建、SDK原生删除适配、共享存储清理、引用完整性、
失败重试/凭证查询、前端导航与缓存更新，以及完整本地和真实环境验收。
已检查固定版本 SDK 0.2.143 的公开 `delete_session(session_id, directory)` 接口，
后续集成需隔离其配置目录、处理支线清理失败并验证实际字节消失，不能只删应用索引。

## 验证

`test_erasure_files.py` 使用真实子进程在清单发布、首个 unlink、共享文件替换、
凭证写入和完成改名后退出，再由新实例恢复；另测授权撤销、源变更、路径攻击、
替换字节损坏、容量、私有权限和冷备份互斥。
`test_data_operations.py` 验证真实 ASGI 请求、流式响应、独立后台任务、取消后
仍存活的线程、业务服务与店铺宿主、跨域忙状态、启动恢复和不完整冷备份拒绝。
这些证据不替代尚未完成的项目/会话删除端到端验收。
