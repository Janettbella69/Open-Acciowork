# 项目与会话删除：实施合同

**状态：会话删除和整个项目删除已接通本地 API 与中英文确认界面。**
会话删除保留独立保存的项目成果；项目删除清理项目、工作区、历史、自动化和项目授权。
二者均支持授权核对、原生 SDK 清理、共享上下文清理及中断恢复。
这不表示 PRD §3.9 全部交付，也不表示真实生产或浏览器目视验收通过。
所有本批删除验证仅使用测试临时目录，没有操作真实用户项目。

## 已实现的事务边界

`erasure_files.py` 接收由主机业务服务构造的精确计划：待删除文件、待移除空目录、
共享文件中需要保留的字节，以及由调用方验证的最小范围/身份信息。它没有 HTTP、
CLI 或 Agent 工具入口；**不能把未经范围校验的用户文件列表直接交给它**。

1. 调用方授权、源文件长度/哈希、目录完整性和保留字节先核验，再次复验后提交。
   计划限制源内容合计 2 GiB、单文件 250 MB、20,000 文件及20,000目录、32层路径；
   单份保留内容16 MiB、合计64 MiB，整个事务记录最多16 MiB。
2. `.data-erasure/pending/` 的原子发布是不可逆提交点。提交前源数据不变；提交后
   中断需要继续清理，不能把已删除内容恢复回来。暂存区只存保留字节和清单，
   不备份将要删除的正文。
3. 删除文件和原子替换共享记录均校验原值。重启可识别已经完成的步骤，剩余替换
   使用已提交的保留字节；部分临时替换可恢复。目录只在为空时移除，额外文件、
   损坏记录、变更源字节或不安全路径使清理失败，不扩大删除范围。
4. 完成时持久写入不含文件正文/路径清单的凭证，再把完整 pending 目录原子改名后
   清理。提交前留下的 staging 和完成后的清理残留可由 `recover()` 清除；损坏的
   pending 不被当作成功。失败后的普通数据访问保持关闭，直到恢复完成。

所有目标路径使用目录描述符，不跟随符号链接，拒绝硬链接、特殊文件、越界路径、
大小写/Unicode别名以及文件/目录冲突。事务不能删除自身清单或互斥锁。保留内容
不能同时位于计划移除的目录中。会话业务层以专用模型保留内容为空的 Run 来源；
通用文件层不推断项目所有权。schema 2 新增受核对的原生 SDK 操作与新建删除标记；
schema 1 的序列化与指纹保持兼容，已有事务可继续恢复。

会话与项目确认处理器在当前授权和有界请求解析完成后，明确交还请求的共享租约，
再由工作线程取得独占租约并复验范围与授权。请求取消不会释放线程的独占租约；
删除入口保留原有请求来源检查和鉴权，没有在持有共享租约时尝试升级。

## 与应用运行的互斥

已有冷备份租约继续负责整个应用与停机维护的互斥。新增
`.data-operation.lock` 负责应用内操作与删除事务的互斥，二者目的不同：

- API 请求在身份 nonce 写入之前取得共享租约，持有到完整 ASGI 响应/流结束。
  维护冲突返回409、`no-store`、`Retry-After`，保留配置的跨域响应策略。
- 独立 Run、定时扫描、前瞻意图、渠道投递和 Web Push 持有各自的租约；请求取消
  后仍工作的上传/编辑/导出等线程也自行持有租约，不依赖请求协程存活。
- 店铺浏览器宿主从构造到退出都参与租约，避免关闭 API 后浏览器仍写登录目录。
- 新进程在创建业务存储前恢复已提交的删除；另一个活进程仍持有独占租约时，
  不争抢其事务。冷备份及恢复验收拒绝未完成的删除记录，不复制或认可半完成状态。

这是一台主机、一个数据目录内的协作锁协议。当前删除独占整个部署的数据操作，
长时 Run、下载流或打开的店铺浏览器会阻止其取得锁；不强行终止它们。旧版本进程、
绕过应用直接改文件的工具、跨主机/不支持 flock 的存储、同 OS 权限攻击者不在
本批保证范围内。上线实际删除前须升级所有写入进程，不能混用不识别此锁的旧版本。

## 会话删除的已交付范围

- `GET /api/projects/{project_id}/conversations/{run_id}/deletion`：当前项目所有者/管理员
  核对，返回项目版本、续接 Run 集合、文件/记忆数量、保留项、请求 ID、时间和指纹。
  本地模式只接受本地操作者；其他租户/无权用户不能取得范围或内容。
- 同路径 `POST`：严格 `confirm_deletion=true`，绑定核对的 ID、时间、指纹。
  24 小时后须重新核对；新增续接、正文/事件/共享数据变更、活动 Run、范围冲突、
  不安全链接或未完成写入都使提交失败。提交点前再次检查当前权限。
- 范围沿原生会话 ID 和双向续接来源关系选取全部关联 Run。删除 Run 事件、摘要、
  任务上下文等目录内容；仅保留严格校验的 `ErasedRun`。它不含 prompt、Provider
  快照、授权参数或回复；获取/列出/重试/续接不能把它当成 Run，同 ID 也不能重建。
- 原生 SDK 的公开 `get_session_info` / `delete_session` 在独立子进程中执行，
  仅传入该 Provider 的 `CLAUDE_CONFIG_DIR`，不继承宿主凭据。先验证工作目录、
  唯一 UUID、源文件和子目录，再提交；SDK 忽略的支线清理失败由精确事务继续完成。
  删除后同步目录；主 transcript 已消失而支线尚在的中断可以继续恢复。
- 同时清理配置目录内可精确归属此 session 的 file-history、tasks、debug、uploads、
  image-cache、session-env、旧 todos、历史行及 transcript 替代副本。归属不清的
  孤儿/重复 transcript 拒绝自动删除，不按模糊路径扩大范围。目录语义参考
  [Claude 官方存储目录说明](https://code.claude.com/docs/en/claude-directory)，实际
  SDK API 使用仓库固定版本 0.2.143，而非假定当前 CLI 全部行为已覆盖。
- `MemoryProvider` 规划源记忆的全版本/历史清理与不含正文的删除标记；Agent
  `MEMORY.md` 只去掉相应 marker 行，保留手写内容。精确移除日记条目、manifest
  记录、通知、反馈、授权和渠道投递；任务经验有相关版本时删除整个经验条目，
  不重新激活旧版本。意图仍在收尾时拒绝删除；保留自动化计数和幂等书签，防止重放。
- 团队讨论保留人工正文，去掉 Run/消息锚点的正文摘要；Skill 候选保留冻结包和
  人审记录，清空来源 prompt 摘要。已保存文件、证据、决策、模板和商业审计保留。
  工作区检查点、项目导出、候选来源校验和冷备恢复识别内容为空的来源标记。
- 同一请求在成功后可以重试，并返回相同关联 Run 集合。前端明确展示不可撤销、
  保留项和勾选确认；断开不能被描述为取消。成功后清空会话/事件/文本/权限/遥测，
  关闭旧 SSE，加载剩余会话；迟到结果不能覆盖用户切换后的项目。

## 整个项目删除的已交付范围

- `GET /api/projects/{project_id}/deletion`：项目所有者/管理员核对项目名称、全部 Run、
  文件、原生会话、记忆、计划、意图、店铺登录、设备授权和独立模板副本数量。
  同路径 `POST` 必须携带原请求 ID、核对时间、指纹、严格布尔确认，并准确输入项目名称。
  核对有效期24小时；提交前在独占租约内重选范围并复验权限，源数据变化须重新核对。
- 项目目录只保留 `ErasedProject`：ID、身份范围、创建/删除时间、删除操作者、请求指纹，
  以及独立模板副本的来源摘要。它没有名称、目标、证据、决策、文件或正文。
  项目不能再被读取、列出、修改、创建 Run、重新建立工作区或按同 ID 重建。
  全部 Run 清空内容并保留 `ErasedRun`，兼容此前已单独删除的会话。
- 删除完整项目工作区、登记版本、检查点、项目记忆及其历史/删除记录、讨论、模板及
  Skill 候选、来源凭证、商业执行审计、定时任务、前瞻意图、任务经验、反馈、通知、
  渠道投递和身份绑定、项目成员/店铺授权。已发布的共享 Skill 保留。
  属于此项目的评论/店铺授权原子写入临时副本一并清理，其他项目副本不变。
- 删除店铺配置和店铺独立浏览器目录（包含登录态）。打开的浏览器会通过操作租约
  阻止提交，需先关闭。共享移动设备只移除此项目范围；没有其他项目的设备配对和
  Push 订阅一并删除。全局不含正文的渠道重放记录保留，防止历史请求被重放。
- 经 `MemoryProvider` 清理项目记忆和有本项目 Run 来源的共享记忆/镜像；共享 Agent
  日记精确去掉相关 Run 块，manifest 去掉项目/Run 条目，保留其他内容和手写共享文件。
- 固定 SDK 的公开 `list_sessions` 发现尚未写入 Run 的项目会话，禁用其他 worktree
  遍历并验证实际 cwd。即使工作区已不存在，也通过安全父目录核验后清理。
  已验证的原生项目目录、session 附属数据、项目历史行和 `.claude.json` 项目项纳入
  事务；配置凭据和其他项目项保留。无法通过公开 API 核验的孤儿缓存不作扩大推断。
- 其他项目从模板复制得到的文件与设置保持独立。删除模板来源后保留无正文的来源摘要，
  冷备份继续验证复制来源与文件版本。删除模板创建的目标时清理上游创建请求和暂存；
  重试同一创建 ID 不能复活已删项目。来源已删除时同步移除其目标摘要。
- 成功后仅原删除操作者在仍有组织 owner/admin 身份、有效认证且租户相同时，可以用
  相同请求 ID/指纹重试，已删除的成员列表不再用于授权；本地模式限本地操作者。
  重试返回完成状态，其他请求不能接管。断网或关闭面板不会取消已提交的删除。
- 前端需要显式核对、输入项目名和勾选确认。成功后移除项目列表项，关闭旧 SSE，
  清空相关会话/事件/文本/权限/遥测和草稿，回到新项目入口；迟到的读取不能重建项目，
  迟到的删除结果也不能清空用户已切换到的其他项目。

## 保留项与尚未交付

删除单个会话保留项目成果及工作区版本，因此保存的文件可能仍引用会话内容。
其他会话（包括已引用这些内容的历史上下文）、其他项目独立副本、人工讨论、模板、
共享/已发布 Skill、商业副作用凭证、自动化配置和书签、凭据、浏览器登录态、
既有备份和外部服务数据不在此删除范围内。无法精确归属的运行缓存、系统临时文件、
文件系统快照及物理介质残留也不在保证范围；界面核对明确列出这些边界。
本功能是应用可恢复内容的逻辑清理，不宣称覆盖底层介质安全擦除。

整个项目删除同样保留其他项目的独立副本、已发布共享 Skill、全局凭据、共享手写
Agent 文件、不含正文的来源记录、既有备份及外部服务数据。无法归属的运行/系统缓存
不在清理保证内；这不是物理介质擦除。旧备份仍可能包含此前的项目内容。
完整应用冷备份与新目录恢复已有独立[本机维护界面](application-backup.md#本机维护界面)。
原生 SDK 完整会话迁移、部署根凭据的真实网关联调、部署自动切换、
跨宿主/生产故障与容量验收、浏览器目视验收保持开放。

## 验证

`test_erasure_files.py` 使用真实子进程在清单发布、首个 unlink、共享文件替换、
凭证写入和完成改名后退出，再由新实例恢复；另测授权撤销、源变更、路径攻击、
替换字节损坏、容量、私有权限和冷备份互斥。
`test_data_operations.py` 验证真实 ASGI 请求、流式响应、独立后台任务、取消后
仍存活的线程、业务服务与店铺宿主、跨域忙状态、启动恢复和不完整冷备份拒绝。
`test_conversation_erasure.py` 覆盖真实固定 SDK 的合成 transcript/支线清理、
原生清理中断恢复、身份与路径攻击、双向续接、HTTP 确认/重试、共享记忆镜像、
讨论与 Skill 来源清理、保留成果/工作区版本、冷备往返和禁止同 ID 重建。
`test_project_erasure.py` 覆盖完整项目与原生未索引会话清理、工作区缺失、自动化、店铺
登录态、共享设备范围、原子写入残留、独立模板副本与源/目标先后删除、冷备往返、
禁止重建、已删会话、授权过期/撤销、中断恢复和 HTTP 严格确认/幂等重试。
前端组件和 runtime hook 测试覆盖准确名称/勾选确认、单次提交、断线重试、取消预览、
卸载后的已提交响应，以及导航、初始列表、项目刷新和旧 SSE 的迟到响应。
全部使用临时合成数据；这些证据不替代真实生产验收。
