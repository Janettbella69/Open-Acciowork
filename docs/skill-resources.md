# 内置 Skill 的参考文件与产物模板（FR-12）

内置的 13 个 Skill 包含各自的输入/证据参考文件和可编辑输出模板。
这些文件与 `SKILL.md` 一起扫描、计算内容指纹、保存不可变版本并固定到 Run。
修改参考文件或模板也会产生不同的包指纹，不能静默改变已经固定的任务。

模板提供结构，不能替代实际研究或计算；没有证据的栏位应明确待核实，
不填入示例数值、虚构来源或交易承诺。主 Agent 按目标选择必要章节，
将模板复制到项目 workspace 后填写，最后通过既有产物工具登记。
全局证据分类规则仍由 `global-opportunity-execution/references/evidence-rules.md` 维护。

## 原生 SDK 读取边界

SDK 只加载本次 Run 固定且符合当前组织策略的 Skill。`options.skills` 指定的
方法加载沿用原生自动批准；Skill 内后续调用的工具仍逐项经过宿主权限规则。
读取方法本身不会新建一个人工审批等待。

`Read`、`Glob`、`Grep` 现在可访问已物化 Plugin 下的 `skills/` 目录。
SDK 启动命令 hook 与普通 Python hook 都从该次实际 Plugin 列表绑定相同读取范围，
不会临时改用 Registry 最新版本，也不会开放整个版本历史或其他运行快照。
运行期间持有既有跨进程只读缓存租约，防止清理器删除仍需懒加载的参考文件。
这些固定参考文件的读取结果保留方法指令；项目文档与其他快照仍按不可信数据处理，
不能通过复制文件或引用别的版本获得方法权限。

`Write`、`Edit` 仍限于当前 workspace。路径检查会解析符号链接；指向围栏外的
参考文件链接会被拒绝，敏感凭据路径规则继续生效。此处说明的是原生文件工具的
宿主权限范围，不代替 Bash 沙箱、生产 worker 隔离或多租户存储隔离。

## 验证边界

资源回归验证从真实 Plugin 包生成不可变快照，读取 Markdown 引用、更新包内容并
验证旧快照保持原文、复制模板后编辑 workspace 副本。SDK 权限回归覆盖已固定参考
文件的读取、禁止写回、其他快照/Registry 路径拒绝、符号链接逃逸和启动 bridge。
真实 Provider 验收与 Skill 回滚/备份恢复演练分别记录，不能以这些本地检查代替。
