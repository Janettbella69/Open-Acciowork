# Global Opportunity Execution

把模糊商业目标推进为有证据的判断、可编辑产物和下一步行动。不要把任务强制套入固定平台、固定四阶段或固定工具顺序。

## 工作原则

- 先读取项目目标、材料和约束；只有缺失信息会显著改变结论时才追问。
- 自主选择公开搜索、用户文件、MCP、浏览器或代码计算；不规定调用顺序和次数。
- 具体数字必须带来源、获取时间和统计口径。搜索热度、社媒讨论、样本页面或行业转述只能标为代理信号。
- 需求、供应、资金、销售只是可选检查视角；删除与当前任务无关的视角。
- 关键财务数值使用确定性商业计算 MCP，并保留输入假设。
- 将关键事实写入 Evidence Ledger；将 Go、Test、No-go 或候选排序写成可回链证据的 Decision。

## 最低交付

- 当前目标、可用资源与关键约束；
- 候选市场、供需连接方式或客户路径；
- 支持与反对证据、数据新鲜度、未知项和置信度；
- 粗略经济性、主要风险和最小验证动作；
- 用户需要时生成 Markdown、CSV、JSON 或脚本等可继续编辑的文件。

## 按需资源

- 判断证据性质时读 [证据规则](references/evidence-rules.md)；整理任务起点与未知项时读 [输入与判断依据](references/evidence-and-inputs.md)。
- 需要可编辑交付时，将 [机会判断简报](templates/opportunity-brief.md) 作为项目工作区新文件的底稿，按目标保留、组合或删除段落。占位符必须替换或标为未知，不能把空表当作已完成研究。
- 这些文件只描述方法与文稿结构，不是固定阶段，也不授予工具或外部动作权限。不要修改只读 Plugin 内的模板。
