# 询盘和谈判的输入与证据

## 具体输入

- RFQ 明确产品规格/版本、目标市场、采购数量与单位、包装、质量验收和所需文件；缺失写 unknown。
- 记录询盘主体与真实收件人出处、沟通语言和目的；没有联系人就保留空缺，不构造邮箱。
- 目标条款包括报价币种、计价单位、Incoterms 版本与指定地点、税费口径、交期起算点和付款节点。
- 分清用户期望、不得突破的约束和可交换条件；数量预测不等于已承诺采购量。
- 还价需要原报价文件或消息及有效期、型号、阶梯数量、MOQ、模具/样品费、运费、付款与交期。

## 证据层级与核对

- 供应商报价/回函支持“供应商曾给出该条款”，不自动证明产能、证书或履约能力。
- 每条报价保留文件路径及页/行或真实消息定位、报价版本、日期、有效期和联系人主体。
- 用户确认的预算和采购限制标作用户陈述；谈判目标、可接受区间和预计让步标作内部假设。
- 检测、公司信息或产能材料按原始出处核对适用主体和型号；口头承诺保留“待书面确认”。
- 报价比较保留原币种原单位；换算要有真实汇率出处、日期、方向及计算过程。
- 只有规格、数量档、贸易条件和费用覆盖可比时才比较总价；缺字段写 unknown，不当成零费用。
- MOQ 区分每 SKU、每颜色与整单，交期区分备货、生产、离港和到货；不能直接混排排名。
- 每个对外提议链接内部真实证据锚点；不向供应商自动披露底价、竞品机密或未授权用户材料。

## 选择与输出方法

- 首次询盘优先让供应商回填缺失条款；还价则围绕已知报价中的具体可谈项提出条件交换。
- 可按数量档、付款节点、包装、交期或样品安排设计备选方案；不给没有依据的“市场底价”。
- compare_supplier_quotes 只计算提供的数据；明确哪些项未被工具覆盖，不能把结果当作供应商信誉评分。
- 用“请确认/是否可提供”区分待核实条款；“接受/同意/下单”只出现在用户确已授权的范围。
- 把内部谈判目标与可外发正文分开；外发版本仅包含经审阅的收件人、正文和附件。
- 草稿可由现有 draft_outbound 能力生成；登记产物不代表已发送或已达成协议。
- 回复到达后按条款记录接受、拒绝、反提议及真实来源；没有回函时不更新为已确认。
- 输出适合当前对话的询盘、还价或比较表，无需每次走完整谈判阶段；新 workspace 模板可按需裁剪。
